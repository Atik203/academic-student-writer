# Security policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately. If GitHub private vulnerability reporting is enabled for this repository, use **Security → Advisories → Report a vulnerability**. If that option is unavailable, contact the maintainer privately through the contact route on their GitHub profile. Do not open a public issue for an unpatched vulnerability.

Include the affected file or version, the steps needed to reproduce the issue, and its likely impact. Do not attach confidential research data, unpublished manuscripts, credentials, or personal information. A small synthetic example is preferred.

## Scope

Reports are most useful when they identify a risk such as unintended disclosure of local project content, unsafe handling of paths or symlinks by an included script, or execution of untrusted content as code. The skill's writing advice and AI-generated output are not security guarantees; always review outputs and protect sensitive source material.

## Supported versions

Security fixes are made to the current release. Older versions may not receive updates; upgrade to the latest release before reporting an issue where possible.
